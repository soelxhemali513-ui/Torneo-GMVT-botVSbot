Ricerca.

Come fa GMVT a scegliere la mossa migliore tra miliardi di possibilità? Tutto inizia qui: quattro algoritmi di ricerca che lavorano insieme per esplorare l'albero di gioco in modo intelligente, profondo e veloce.

Iterative Deepening PVS Quiescence Search Aspiration Windows
algoritmo 01

Iterative Deepening

Il modo più ovvio di cercare la mossa migliore sarebbe esplorare subito alla profondità massima. Ma questo ha un problema enorme: non sai quanto ci vorrà, e potresti sforare il tempo limite.

L'Iterative Deepening risolve il problema cercando prima alla profondità 1, poi 2, poi 3… fino al limite di tempo. Ogni iterazione salva la mossa migliore trovata finora: se il tempo scade, hai sempre una risposta valida.
💡
Paradosso dell'efficienza
Sembra uno spreco rieseguire le ricerche superficiali ogni volta. In realtà il costo totale è dominato dall'ultimo livello: con branching factor b=35, la profondità d costa b^d nodi — tutte le profondità precedenti sommate costano circa b/(b-1) ≈ 3% in più. Un trade-off quasi gratuito per avere controllo sul tempo.

bot.cpp — valuta_mossa()
C++
// Calcola il limite di tempo in base alla fase di gioco
int mosse_giocate = (int)storia_mosse.size();
int limite_ms = 1000;
if (mosse_giocate < 16)  limite_ms = 700;   // apertura: più veloce
if (mosse_giocate >= 40) limite_ms = 1300;  // finale: più tempo
if (fase_gioco(scacch) > 180) limite_ms += 200;

int profondita_corr = 1;
const int max_prof = 14;

// ── Iterative Deepening: profondità 1 → 14 ──────────────────
while (profondita_corr <= max_prof)
{
    // Cerca alla profondità corrente
    int miglior_val = -INFINITO;
    for (int i = 0; i < numero_mosse; i++)
    {
        esegui_mossa(scacch, mosse[i].da, mosse[i].a, matto_bot);
        int risultato = -minimax(scacch, profondita_corr - 1, -beta_asp, -alfa_asp, ...);
        annulla_mossa(scacch);
        if (risultato > miglior_val) { miglior_val = risultato; }
    }

    // Controlla il tempo rimasto
    auto trascorso = durata(ora() - inizio);
    if (trascorso.count() >= limite_ms) break;  // tempo scaduto
    profondita_corr++;
}

algoritmo 02

PVS — Principal Variation Search

L'alpha-beta standard cerca tutte le mosse con la stessa finestra [alfa, beta]. Il Principal Variation Search fa un'osservazione furba: dopo aver trovato una buona mossa (la principal variation), le mosse successive probabilmente sono peggiori — non vale la pena cercarle a piena potenza.

Le mosse successive vengono quindi cercate con una finestra nulla [-alfa-1, -alfa] — una semplice verifica "è meglio o no?". Solo se la risposta è sì, si ri-cerca a finestra piena. In pratica, la maggioranza delle mosse viene scartata velocemente.
bot.cpp — minimax() con PVS
C++
for (int i = 0; i < numero_mosse; i++)
{
    esegui_mossa(scacch, mosse[i].da, mosse[i].a, matto_loc);

    int risultato;

    // ── PVS: mosse successive → prima finestra nulla ─────────────
    if (i >= 4 && profondita >= 3
        && !e_cattura && !e_promozione_mossa
        && !in_scacco && !da_scacco)
    {
        // Cerca con finestra nulla: solo "è meglio di alfa?"
        risultato = -minimax(scacch, prof-1-rid, -alfa-1, -alfa, ...);

        if (risultato > alfa)
        {
            // Sorpresa: mossa migliore del previsto → ri-cerca a piena finestra
            risultato = -minimax(scacch, prof-1, -beta, -alfa, ...);
        }
    }
    else
    {
        // Prima mossa (PV) → sempre a finestra piena
        risultato = -minimax(scacch, prof-1, -beta, -alfa, ...);
    }

    annulla_mossa(scacch);
    if (risultato > alfa) alfa = risultato;
    if (alfa >= beta) break;  // cutoff
}
⚡
Combinazione con LMR
Nel codice, PVS è combinato con Late Move Reduction (LMR): le mosse oltre la 4ª vengono cercate sia con finestra nulla sia con profondità ridotta (prof-1-riduzione). Solo un doppio fallback (finestra aperta) recupera la piena qualità di ricerca. Questo rende GMVT molto più veloce nelle posizioni con tante mosse candidate.

algoritmo 03

Quiescence Search

Immagina che la ricerca si fermi con la regina avversaria che sta per catturare un pedone. La valutazione statica direbbe "tutto ok", ma è una bugia: la posizione è tutt'altro che tranquilla (quiet).

La Quiescence Search estende la ricerca oltre la profondità massima, ma valuta solo catture e promozioni — le mosse "rumorose" — finché non si raggiunge una posizione veramente stabile. Questo elimina l'effetto orizzonte, uno dei difetti classici dei motori scacchistici.

bot.cpp — ricerca_quiete()
C++
int ricerca_quiete(scacchiera &scacch, int alfa, int beta, int colore_bot, int prof_qs)
{
    // Evita stack overflow su posizioni tattiche esplosive
    if (prof_qs >= 8) return valutazione(scacch, turno);

    // Stand-pat: valutazione statica come lower bound
    int stand_pat = valutazione(scacch, turno);
    if (stand_pat >= beta) return beta;    // beta cutoff immediato

    // Delta pruning: ignora catture che non possono migliorare abbastanza
    static const int DELTA = 950; // ≈ valore di una regina
    if (stand_pat < alfa - DELTA) return alfa; // troppo indietro

    if (stand_pat > alfa) alfa = stand_pat;

    // Genera e filtra solo mosse tattiche (catture + promozioni)
    Mossa tutte[256]; int totale = genera_mosse(tutte, turno, scacch);
    for (int i = 0; i < totale; i++) {
        bool e_cattura    = (scacch.casa[tutte[i].a] != 0);
        bool e_promozione = (tutte[i].promozione != 0);
        if (!e_cattura && !e_promozione) continue; // scarta mosse silenziose
        // ...ordina per MVV-LVA e valuta ricorsivamente
    }
    return alfa;
}
A
Stand-pat cutoff
Il diritto di non fare niente
Se la valutazione statica è già >= beta, il giocatore ha già una posizione abbastanza buona da rifiutare questa linea. Non serve continuare — è come dire "anche se non catturo, sto già vincendo".
B
Delta pruning
Ottimismo a 950 centipedoni
Se la valutazione statica è già di 950 punti sotto alfa, nessuna singola cattura può recuperare abbastanza. Il valore 950 è scelto perché corrisponde a circa il valore di una regina — la cattura più preziosa possibile.
algoritmo 04

Aspiration Windows

Quando GMVT ha già trovato un valore alla profondità precedente, è ragionevole aspettarsi che il valore alla prossima profondità non sia molto lontano. Invece di cercare con la finestra infinita [-∞, +∞], si usa una finestra ristretta attorno al valore precedente.

Se il risultato cade fuori dalla finestra (fail-low o fail-high), la ricerca viene ripetuta con una finestra più larga. Nella maggioranza dei casi, però, la finestra stretta dimezza il lavoro necessario.

bot.cpp — Aspiration Windows in valuta_mossa()
C++
int finestra = 50;          // ±50 centipedoni intorno al valore precedente
int valore_prec = -INFINITO;

while (profondita_corr <= max_prof)
{
    int alfa_asp, beta_asp;

    // A partire da profondità 4: finestra stretta ±50
    if (profondita_corr >= 4 && valore_prec > -INFINITO / 2)
    {
        alfa_asp = valore_prec - finestra;
        beta_asp = valore_prec + finestra;
    } else {
        alfa_asp = -INFINITO; beta_asp = INFINITO; // finestra piena
    }

    ri_cerca = false;
    /* ... esegui la ricerca ... */

    if (miglior_val <= alfa_asp)       // fail-low
    {
        alfa_asp = -INFINITO; ri_cerca = true; // apri finestra verso il basso
    }
    else if (miglior_val >= beta_asp)  // fail-high
    {
        beta_asp = INFINITO; ri_cerca = true;  // apri finestra verso l'alto
    }
    valore_prec = miglior_val;
}
🎯
Perché ±50 centipedoni?
50 centipedoni equivale a circa metà pedone. Nella maggior parte delle posizioni di gioco normale, il valore non cambia di più tra una profondità e la successiva. Un valore più piccolo causerebbe troppi fail (ri-ricerche costose), uno più grande ridurrebbe i benefici dell'ottimizzazione.
riepilogo

Come lavorano insieme

I quattro algoritmi non sono indipendenti: sono strati che si potenziano a vicenda ogni volta che GMVT deve muovere.

  • 1
    Iterative Deepening lancia la ricerca alla profondità 1 e incrementa. Ogni iterazione usa i risultati della precedente per ordinare meglio le mosse (tramite la TT).
  • 2
    Aspiration Windows restringe la finestra alpha-beta ad ogni iterazione, partendo dal valore trovato nell'iterazione precedente. Risparmia fino al 30-40% dei nodi in posizioni stabili.
  • 3
    PVS dentro ogni chiamata a minimax cerca la prima mossa a piena finestra, poi usa la finestra nulla per verificare rapidamente le restanti. Solo i fail-high causano ri-ricerche costose.
  • 4
    Quiescence Search entra in gioco quando la profondità scende a 0. Estende la ricerca sulle posizioni "calde" (catture aperte) per evitare valutazioni ottimiste su scambi di materiale in corso.
