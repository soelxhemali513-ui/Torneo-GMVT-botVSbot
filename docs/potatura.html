Potatura.

Cercare ogni mossa possibile è impossibile: ci sono più posizioni scacchistiche che atomi nell'universo. La potatura elimina i rami inutili prima di esplorarli, rendendo la ricerca centinaia di volte più veloce senza perdere qualità.

algoritmo 01

Alpha-Beta Pruning

L'Alpha-Beta Pruning è il cuore del motore: una versione ottimizzata di Minimax che mantiene due valori, α (il meglio che il massimizzatore può garantire) e β (il meglio che il minimizzatore può garantire). Quando β ≤ α, la ricerca del sottoalbero corrente viene interrotta: nessun risultato può influenzare la decisione finale.

Nel caso peggiore, Alpha-Beta esplora gli stessi nodi di Minimax. Nel caso ottimale (mosse ordinate perfettamente) riduce il fattore di ramificazione da b a √b — raddoppiando la profondità raggiungibile a parità di tempo.

minimax.cpp C++ 
int minimax(Scacchiera& s, int prof, int alfa, int beta)
{
    if (prof == 0) return quiescence(s, alfa, beta);

    for (auto& mossa : genera_mosse(s))
    {
        esegui_mossa(s, mossa);
        int val = -minimax(s, prof-1, -beta, -alfa);
        annulla_mossa(s, mossa);

        if (val >= beta)
            return beta;  // ✂ beta cutoff: il padre minimizzatore ignorerà questo

        if (val > alfa)
            alfa = val;  // nuovo lower bound
    }
    return alfa;
}
💡
Ordine delle mosse — chiave per l'efficienza
L'efficacia di Alpha-Beta dipende criticamente dall'ordine in cui le mosse vengono esaminate. GMVT ordina: catture (MVV-LVA), mosse killer, mosse della TT, history heuristic. Con ordinamento ottimale si raggiunge il caso O(bd/2).
algoritmo 02

Null Move Pruning

Il Null Move Pruning (NMP) si basa su un'idea semplice: se il giocatore non fa nulla (passa il turno) e la ricerca ridotta ritorna ancora un valore > β, allora la posizione è talmente buona per il giocatore corrente che qualsiasi mossa reale sarà almeno altrettanto buona — quindi possiamo tagliare il ramo.

In GMVT viene applicato con riduzione R = 3 (la ricerca null viene fatta a profondità prof - R - 1) e viene disattivato in posizioni di zugzwang (solo pedoni, finale).
Riduzione R
3 ply
Risparmio
~15-25%
Disattivato
Zugzwang
null_move.cpp C++ 
// NMP: prova a passare il turno e cerca con profondità ridotta
if (!in_scacco && prof >= 3 && !solo_pedoni(s))
{
    esegui_mossa_nulla(s);  // passa il turno
    int val = -minimax(s, prof - 3 - 1, -beta, -beta+1);
    annulla_mossa_nulla(s);

    if (val >= beta)          // anche senza muovere, siamo oltre β
        return beta;          // ✂ cutoff garantito
}
⚠️
Zugzwang — il caso pericoloso
Nei finali con solo pedoni, qualsiasi mossa potrebbe peggiorare la posizione (zugzwang). In questi casi NMP è disattivato perché passare il turno darebbe un'immagine falsamente positiva della situazione.
algoritmo 03

Reverse Futility Pruning

Il Reverse Futility Pruning (RFP) — anche detto static null move pruning — è una tecnica che evita di esplorare un nodo quando la valutazione statica è già così alta da superare β di un margine prestabilito. In pratica: se la posizione è talmente buona senza neanche cercare, non vale la pena continuare.

In GMVT il margine cresce con la profondità residua: margine = 80 × prof.
Margine base
80 cp
Margine a d=3
240 cp
Profondità max
d ≤ 6
rfp.cpp C++ 
// RFP: taglia se eval statica supera β di abbastanza
if (prof <= 6 && !in_scacco)
{
    int eval = valuta(s);
    int margine = 80 * prof;

    if (eval - margine >= beta)   // anche nel caso peggiore siamo sopra β
        return eval - margine;   // ✂ RFP cutoff
}
// Schema RFP: se la valutazione statica supera β di almeno il margine, il nodo viene potato
algoritmo 04

Late Move Reduction (LMR)

Le ultime mosse nell'elenco dei candidati (quelle con score di ordinamento più basso) hanno meno probabilità di essere buone. LMR le cerca a profondità ridotta: se il risultato ridotto supera α, allora — e solo allora — viene fatta una ri-ricerca a profondità piena.

In GMVT la riduzione base è di 1 ply per le mosse oltre la 4ª, con un incremento logaritmico per profondità e numero di mossa: R = 1 + log(prof) × log(nmossa) / 2
Attiva da
mossa 4+
Riduzione min
1 ply
Risparmio
~30-40%
lmr.cpp C++ 
int nmossa = 0;
for (auto& m : mosse_ordinate(s))
{
    esegui_mossa(s, m); nmossa++;

    int rid = 0;
    if (nmossa > 4 && prof >= 3 && !in_scacco && !e_cattura(m))
        rid = 1 + (int)(log(prof) * log(nmossa) / 2.0);  // riduzione LMR

    int val = -minimax(s, prof-1-rid, -alfa-1, -alfa);
    if (val > alfa && rid > 0)
    {
        val = -minimax(s, prof-1, -beta, -alfa); // ri-cerca piena
    }
    annulla_mossa(s, m);
    if (val >= beta) return beta;
    if (val > alfa) alfa = val;
}
algoritmi 05–06

ProbCut & Mate Distance Pruning

05
ProbCut
Taglio probabilistico a profondità ridotta
Prima di esplorare un nodo a profondità piena, GMVT esegue una ricerca superficiale (prof - R). Se il risultato supera una soglia beta + margine con alta probabilità, il nodo viene tagliato. Utile specialmente nelle catture dove il guadagno materiale è già evidente.
06
Mate Distance
Potatura basata sulla distanza dal matto
Se il bot ha già trovato un matto a N mosse, non serve esplorare rami che portano a un matto più lungo. GMVT adatta α e β in base alla distanza massima possibile da matto: alfa = max(alfa, -MATTO + ply). Elimina molte ricerche inutili nei finali tattici.
mate_distance.cpp C++ 
// Mate Distance Pruning — eseguito all'inizio di ogni nodo
const int MATTO = 32000;

int matto_alpha = -MATTO + ply;
int matto_beta  = MATTO  - ply;

if (matto_alpha >= beta)  return matto_alpha;
if (matto_beta  <= alfa)  return matto_beta;

alfa = max(alfa, matto_alpha);  // stringe la finestra verso il matto vicino
beta = min(beta, matto_beta);
